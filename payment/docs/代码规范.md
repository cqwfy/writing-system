# 中学学生管理系统 — 代码规范

## 1. 通用规范

### 1.1 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| 文件名 | 小写 + 短横线 / 小驼峰 | `auth.controller.ts`, `useAuth.ts` |
| 变量 | 小驼峰 | `studentName`, `isLoading` |
| 函数 | 小驼峰，动词开头 | `getStudentById()`, `handleLogin()` |
| 类 / 接口 | 大驼峰 | `StudentService`, `UserDTO` |
| 常量 / 枚举 | 全大写 + 下划线 | `MAX_UPLOAD_SIZE`, `Role.ADMIN` |
| 数据库表 | 小写 + 下划线，复数 | `students`, `exam_types` |
| 数据库列 | 小驼峰 | `studentNo`, `createdAt` |
| 类型文件 | `.d.ts` 后缀 | `express.d.ts` |

### 1.2 缩进与格式

- **后端 (TypeScript/Express)**: 2 空格缩进
- **前端 (React/Admin)**: 2 空格缩进
- **小程序**: 2 空格缩进
- **每行不超过 120 字符**
- 使用 Prettier 自动格式化

### 1.3 注释规范

- 使用 **中文注释** 说明业务逻辑
- 变量/函数名已能自解释时，不需要注释
- 仅在 WHY 不显而易见时添加注释（如边界条件、临时 workaround）

```typescript
// ✅ 好的注释——解释为什么
// 需要单独处理，因为 Prisma 的 soft delete 中间件不作用于 findUnique
const student = await prisma.student.findUnique({ ... });

// ❌ 多余的注释——代码已说明一切
// 根据 ID 获取学生
const student = await getStudentById(id);
```

### 1.4 函数规范

- 单一职责，一个函数不超过 50 行
- 参数不超过 4 个，超过使用对象参数
- 同步函数不要返回 Promise

```typescript
// ✅ 好的参数设计
async function listStudents(params: {
  page: number;
  pageSize: number;
  keyword?: string;
  classId?: number;
}): Promise<PaginatedResult<StudentDTO>> { ... }
```

## 2. 后端规范

### 2.1 项目结构

```
packages/server/src/
├── config/          # 环境配置
├── controllers/     # 请求处理（薄层，仅参数提取和响应）
├── services/        # 业务逻辑（核心逻辑层）
├── middleware/       # 中间件（认证、授权、错误处理）
├── routes/          # 路由定义
├── prisma/          # ORM Schema 和迁移
├── utils/           # 工具函数
└── types/           # 类型扩展
```

### 2.2 分层职责

```
Route → Controller → Service → Prisma Client
  │         │           │
  │         │           └── 业务逻辑 + 事务管理
  │         └── 参数校验 (Zod) + 响应格式化
  └── HTTP 方法 + 路径 + 中间件链
```

**Controller 层** — 薄层：
```typescript
// ✅ 好的 Controller——只做参数提取和响应
async createStudent(req: Request, res: Response, next: NextFunction) {
  try {
    const data = createStudentSchema.parse(req.body);
    const result = await studentService.create(data);
    res.status(201).json({ data: result });
  } catch (err) {
    next(err);
  }
}
```

**Service 层** — 业务逻辑：
```typescript
// ✅ Service 包含所有业务规则
async createStudent(data: CreateStudentInput) {
  const exists = await prisma.student.findUnique({ where: { studentNo: data.studentNo } });
  if (exists) throw new AppError(409, "学号已存在");
  return prisma.student.create({ data });
}
```

### 2.3 错误处理

- 使用统一的 `AppError` 类
- 不要在 Controller 中 try-catch，统一交给 `errorHandler` 中间件
- Zod 校验错误由 errorHandler 自动转换为 400 响应

```typescript
// ✅ 抛业务错误
throw new AppError(404, "学生不存在");
throw new AppError(400, "房间容量不足，剩余 2 个床位");
throw new AppError(403, "您没有权限执行此操作");

// ✅ Controller 中用 .catch(next) 或用 try-catch 后 next(err)
async handler(req, res, next) {
  try { ... } catch (err) { next(err); }
}
```

### 2.4 路由定义

```typescript
// ✅ 统一的中间件链
router.get("/", authMiddleware, rbacMiddleware(Role.ADMIN, Role.TEACHER), controller.list);
router.post("/", authMiddleware, rbacMiddleware(Role.ADMIN), controller.create);
router.get("/my", authMiddleware, controller.getMyOwn);
```

### 2.5 数据库操作

- 使用 Prisma 事务处理多表操作
- 敏感字段（idCard）在 Repository 层加解密
- 查询时注意 N+1 问题，合理使用 `include`

```typescript
// ✅ 事务处理
await prisma.$transaction(async (tx) => {
  await tx.student.update({ where: { id }, data: { dormitoryId: roomId } });
  await tx.dormitoryRoom.update({ where: { id: roomId }, data: { occupied: { increment: 1 } } });
});
```

## 3. 前端规范 (React/Admin)

### 3.1 组件结构

```
src/
├── pages/           # 页面级组件（对应路由）
├── components/      # 可复用组件
├── hooks/           # 自定义 Hooks
├── services/        # API 调用层
├── stores/          # 状态管理 (Zustand)
├── utils/           # 工具函数
└── layouts/         # 布局组件
```

### 3.2 组件编写

- 使用函数组件 + Hooks
- React Hooks 必须在组件顶层调用，不能在 render 回调（如 `Form.List` 的 children）中使用

```tsx
// ✅ 好的写法——Hook 在组件顶层
export function DormitoryPage() {
  const watchedStudents = Form.useWatch("students", assignForm) || [];
  // ...
  return (
    <Form.List name="students">
      {(fields, { add, remove }) => fields.map(({ key, name }) => {
        const rowValue = watchedStudents?.[name];
        // 不要在这里调用 Form.useWatch ❌
      })}
    </Form.List>
  );
}
```

### 3.3 API 调用

```typescript
// ✅ 统一使用 api service
import api from "../services/api";

const res = await api.get("/students", { params: { page: 1, keyword: "张三" } });
const res = await api.post("/students", { name: "新学生", ... });
const res = await api.put(`/students/${id}`, { name: "修改后" });
const res = await api.delete(`/students/${id}`);
```

### 3.4 状态管理

- 全局认证状态使用 Zustand：`useAuthStore()`
- 页面内状态使用 `useState` / `useEffect`
- 不要在多个 state 间产生循环依赖

### 3.5 表格与表单

- 列表页优先使用 `@ant-design/pro-components` 的 `ProTable`
- 弹窗表单使用 Ant Design `Modal` + `Form`

## 5. Git 规范

### 5.1 分支策略

```
main           # 生产分支
├── develop    # 开发分支
├── feature/*  # 功能分支
├── fix/*      # 修复分支
└── release/*  # 发布分支
```

### 5.2 提交信息规范

```
<类型>(<范围>): <简短描述>

类型：
  feat     - 新功能
  fix      - Bug 修复
  refactor - 重构（不改变功能）
  docs     - 文档更新
  style    - 代码格式（不影响逻辑）
  chore    - 构建/工具/依赖变更
  test     - 测试相关

范围（可选）：
  api       - 后端接口
  admin     - Web 管理后台
  miniapp   - 微信小程序
  db        - 数据库
  shared    - 共享包

示例：
  feat(api): 新增学生 Excel 批量导入接口
  fix(admin): 修复宿舍分配弹窗 React #321 错误
  refactor(api): 提取成绩排名计算为独立方法
  docs: 完善 API 接口文档
```

### 5.3 提交前检查

- 代码已通过 TypeScript 类型检查
- 不提交 `.env`、`node_modules`、`dist` 等文件
- 不包含硬编码密钥或密码
- 提交信息正确描述变更内容

## 7. 安全规范

### 7.1 禁止事项

- **禁止** 硬编码密钥、密码、Token 到代码中
- **禁止** 提交 `.env` 文件到 Git
- **禁止** 在日志中输出密码或身份证号
- **禁止** 使用 `eval()`、`new Function()` 等动态执行
- **禁止** 拼接 SQL 字符串（使用 Prisma 参数化查询）

### 7.2 数据保护

- 身份证号：AES-256 加密存储，API 仅返回后 4 位
- 手机号：非管理员角色中间 4 位显示为星号
- 密码：bcrypt 加盐哈希，绝不存储明文
- JWT：使用安全的 secret，accessToken 2h 过期

### 7.3 API 安全

- 所有管理类接口必须通过 `authMiddleware` 认证
- 敏感操作通过 `rbacMiddleware` 权限检查
- 学生/家长操作通过 `ownershipMiddleware` 数据所有权过滤
