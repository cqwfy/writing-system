# 公众号写作 · 完整工作流

## 一、任务类型判断

收到公众号写作任务后，先判断任务类型：

| 类型 | 触发条件 | 流程 |
|------|----------|------|
| A - 新写作任务（有完整brief） | 用户提供了明确的主题、角度、要求 | 完整 9 步流程 |
| B - 新写作任务（无brief只有需求） | 用户只说了想写什么，没具体要求 | 先讨论明确需求 → 保存brief → 完整 9 步 |
| C - 修改已有文章 | 对已发布或已完成的文章进行修改 | 读取原文 → 理解需求 → 修改 → 审校 |
| D - 文章审校/降AI味 | 已有初稿，只需要审校 | 直接执行三遍审校（Step 8） |
| E - 快速咨询 | 写作相关的问题、选题想法讨论 | 直接回答，用 Think Aloud |

---

## 二、公众号写作 9 步流程

### Step 1: 理解需求 & 保存 Brief

**目标**：把写作需求固化为可追溯的文档。

**操作**：
1. 与用户沟通，明确以下要素：
   - 文章主题是什么？
   - 目标读者是谁？
   - 核心信息/观点是什么？
   - 有没有特殊要求（字数、风格、截止日期）？
2. 将 brief 保存到 `_briefs/` 文件夹
3. 文件名格式：`主题-brief.md`

**Brief 模板**：
```markdown
# [文章主题] - Brief

**创建日期**：YYYY-MM-DD
**目标读者**：
**核心信息**：
**字数范围**：
**特殊要求**：
**参考资料**：
```

**如果用户只给了模糊需求（类型 B）**：
- 先用提问明确以上要素
- 不要自己假设
- 明确后再保存 brief

---

### Step 2: 信息搜索与知识管理 ⭐

**何时必做**：
- 写作涉及 2024-2026 年的新产品、新模型、新技术
- 需要引用具体数据
- 需要竞品对比

**搜索流程**：
1. **官方信息**：产品官网、官方博客、官方发布会
2. **科技媒体**：TechCrunch、The Verge、Ars Technica、36氪、极客公园
3. **社区讨论**：Reddit、Hacker News、Product Hunt、V2EX
4. **竞品对比**：同类产品的差异和优势

**保存知识库**：
- 文件保存到 `_knowledge_base/`
- 格式：`主题-日期.md`
- 必须包含：信息收集时间、来源列表、关键事实摘要、待验证信息

**搜索后 Think Aloud**：
- 简述搜索到了什么关键信息
- 有哪些有趣的发现？
- 有什么信息矛盾需要交叉验证？

---

### Step 3: 选题讨论 ⭐ 必做

**这是最重要的步骤，绝不可跳过。**

提供 3-4 个选题方向，每个包含：

```markdown
### 选题 N：[标题]

**核心角度**：（一句话，这个选题的独特切入点是什么）

**工作量评估**：⭐⭐⭐ （1-3星）
- ⭐ = 纯观点输出，不需要测试/搜索
- ⭐⭐ = 需要搜索 + 整理，可能有简单对比
- ⭐⭐⭐ = 需要大量搜索 + 测试 + 配图

**优势**：
- 为什么这个角度好？

**劣势**：
- 有什么风险或不足？

**是否需要真实测试**：是/否
- 如是，需要测试什么？

**大纲**：
1. 开头（约 X 字）：[怎么写]
2. 主体 1（约 X 字）：[写什么]
3. 主体 2（约 X 字）：[写什么]
4. ...
5. 结尾（约 X 字）：[收束方式]

**预计总字数**：约 XXXX 字
```

**选题讨论的原则**：
- 每个选题的**核心角度必须不同**（不能是同一角度的三个变体）
- 至少有一个选题是"反常识"或"冷思考"角度
- 清楚说明每个选题的优势和劣势
- 等用户选择，不假设用户会选哪个

---

### Step 4: 创建协作文档（如需测试/配图）

如果选题需要真实测试或配图，创建协作文档到 `_协作文档/`。

**协作文档应包含**：

1. **测试任务清单**（如有）
   - 详细步骤
   - 统一的测试 Prompt（如需测试 AI 工具）
   - 数据记录表格模板

2. **配图需求清单**（如涉及）
   - [ ] 必需配图 1：[描述]
   - [ ] 必需配图 2：[描述]
   - [ ] 可选配图 1：[描述]

3. **协作检查清单**
   - [ ] 测试数据已提供
   - [ ] 配图已提供
   - [ ] 关键信息已确认

---

### Step 5: 学习风格

**AI 会阅读**：
1. `写作参考/风格指南.md` — 语言风格定义
2. 历史文章（如有存档）— 至少 2-3 篇
3. `个人素材库/` 中的相关素材

**提取**：
- 开头方式偏好
- 结构组织偏好
- 语言特征（句式长度、词汇选择、节奏）
- 金句风格

**Think Aloud**："我注意到你的文章有以下几个风格特征：..."

---

### Step 5.5: 使用个人素材库 ⭐ 降 AI 味的核心

**方法 A：直接搜索原始素材**

用 Grep/Bash 工具在个人素材库文件中搜索关键词。

比如写 Claude Code 文章 → 搜索 "Claude|Cursor|AI编程"，找到真实的体验和评价。

**方法 B：查看主题索引**

打开 `个人素材库/主题索引.md`，查看是否有相关主题的已整理素材。

**素材使用方式**：

| 文章位置 | 如何使用素材 |
|----------|-------------|
| 开头 | 用真实经历/吐槽引入，建立真实感 |
| 观点支撑 | 用真实评价和判断增强可信度 |
| 案例展示 | 用真实使用体验替代编造的案例 |
| 结尾思考 | 用个人洞察升华主题 |

**重要约束**：
- 所有素材必须真实，不编造不夸大
- 改写成文章逻辑，不直接复制粘贴
- 如果素材库里没有相关素材，诚实标记 "TODO"，不要硬编

**当前素材库有限时的应对**：
- 优先使用你自己的真实判断和观点
- 用"我测了"、"我用了"的口吻写，而不是"数据显示"
- 尽快积累，每次写作后补充新素材

---

### Step 6: 等待测试数据

如果需要真实测试，等待用户完成测试任务。

收到数据和配图后，再开始写作。

**不要在没有数据的情况下编造测试结果。**

---

### Step 7: 创作初稿

**基于真实数据写作。**

**核心要求**：
- 保持"实践 + 落地"的调性
- 加入具体案例
- 自然融入你的经验和视角
- 初稿可以不完美，重点是把内容写出来
- 审校环节会系统化优化

**写作时的风格锚点**：
- 开头要快，3 句内进入正题
- 多用短句（15-25 字为主）
- 每段不超过手机屏幕 5 行
- 有明确的观点和态度，不含糊
- 像在和朋友聊天，不像在写论文

---

### Step 7.5: 风格转换实验（可选）

**这是实验性步骤，不强制。**

可以尝试用不同写作者的风格重新表达某些段落，作为灵感参考。

**可选参考风格**：
- Keso（简短犀利的科技评论）
- 张小龙（产品哲学、极简表达）
- Paul Graham（逻辑推进、层层深入）

**核心原则**：
- 只借鉴语言风格（句式、节奏、思维方式）
- 禁止使用原话（不引用别人的金句）
- 禁止用他人经历（所有经历都必须是你的）

---

### Step 8: 三遍审校（降 AI 味）⭐ 最关键的步骤

#### 第一遍：内容审校（逻辑、事实、结构）

**检查项**：
- [ ] 事实准确？数据、时间、产品名称全部核对
- [ ] 逻辑清晰？前后无矛盾，因果关系成立
- [ ] 结构合理？没有跑题，没有重复段落
- [ ] 无编造？所有数据和案例都真实
- [ ] 关键信息有来源？引用的数据能找到出处

**常见问题**：
- "某数据显示..." → 必须指出是什么数据、来自哪里
- "很多人认为..." → 要么说具体是谁，要么删掉
- "有研究表明..." → 引用具体研究，否则删掉

#### 第二遍：风格审校（AI 味降重）

**这是降 AI 味的核心步骤。**

**AI 味检测清单**（出现任一项即需修改）：

| AI 味 | 问题 | 改写方向 |
|-------|------|---------|
| "在当今时代"、"随着...的发展" | 假大空开头 | 直接进入具体事件或问题 |
| "综上所述"、"总而言之" | 模板化结尾 | 用个人的一句话洞察收尾 |
| "值得注意的是"、"不可忽视的是" | 套话连接 | 直接说内容，不需要预告 |
| "不仅...而且..."、"既...也..." | AI 句式模板 | 拆成两句简单的话 |
| "显著提升"、"充分利用"、"有效促进" | 假大空词汇 | 用具体数字/具体做法替代 |
| "进行操作"、"进行处理"、"进行优化" | 动词名词化 | 直接用动词：操作、处理、优化 |
| 中立客观、不表达态度 | 没有观点 | 每段至少有一个明确判断 |
| 连续三段以上同样的句式结构 | 节奏单调 | 变换句式，长短交替 |

**改写示例**：

❌ "在当今AI技术飞速发展的时代，各类编程辅助工具也在不断涌现和进化..."
✅ "Claude Code 出了。我用了两周，确实好用。"

❌ "通过充分利用AI的强大能力，可以显著提升内容创作的整体效率..."
✅ "用 AI 写文章，我省了一半时间。但也踩了不少坑。"

❌ "这一现象的出现，从某种程度上反映了行业发展的必然趋势..."
✅ "这说明什么？说明行业在变。"

**改写原则**：
- 像说话一样写 —— 大声读出来，不像人话就改
- 每句话都应该有信息量 —— 删除"废话填充"
- 敢于表达观点 —— 不要说"可能"、"或许"，直接说你觉得怎样
- 用具体替代抽象 —— "省了3小时" > "提升了效率"

#### 第三遍：细节打磨（标点、排版、节奏）

**检查项**：
- [ ] 句子长度合适？（15-25 字为主，不超过 30 字）
- [ ] 段落不太长？（手机屏幕 3-5 行为宜）
- [ ] 标点自然？（多用句号，少用逗号连接超长句）
- [ ] 节奏有变化？（快慢结合，长短句交替）
- [ ] 公众号排版友好？（段落间有空行，关键句可加粗）

**操作**：
1. 大声朗读全文，感受节奏
2. 找出所有超过 30 字的长句，拆短
3. 检查段落长度，超过 5 行的拆开
4. 检查标点使用，分号、破折号是否必要

---

### Step 9: 文章配图 ⭐

**如果需要配图**：

1. **分析文章，确定配图需求**
   - 推荐 5-8 张图片
   - 标注哪些是必需的，哪些是可选的

2. **图片获取优先级**
   - 公共领域作品（Wikimedia Commons）
   - AI 生成（火山引擎 API 或其他文生图工具）
   - 免费图库（Unsplash、Pexels）
   - 截图/官方素材（需注明来源）

3. **插入图片**
   - 在 Markdown 中插入，使用相对路径
   - 保存到 `images/[文章主题]/` 目录

4. **验证**
   - 确认所有图片能正常显示
   - 确认图片来源合规

## 三、7 个关键原则

### 1. Think Aloud 透明化思考
每次决策都说明思考过程。让用户知道 AI 在想什么，可以及时纠正方向。

### 2. 调研先行
涉及新产品、新技术时，必须先搜索验证，不依赖训练数据。

### 3. 选题讨论必做
不跳过选题讨论直接写文章。避免方向错误造成大量返工。

### 4. 个人素材库降 AI 味
用真实经历、观点、案例替代 AI 腔。素材库越丰富，文章越像你。

### 5. 三遍审校机制
内容审校（对错）→ 风格审校（像不像人）→ 细节打磨（好不好读）。三步缺一不可。

### 6. 文章配图一步到位
直接完成配图，不要写"此处应配图"然后留给用户。

### 7. 协作文档明确分工
需要用户配合的事，列清楚清单。用户知道自己要做什么，AI 知道自己要等什么。

## 四、公众号特殊注意事项

### 4.1 标题
- 公众号标题要有吸引力但不标题党
- 预留 2-3 个备选标题
- 标题长度控制在 25 字以内（含标点）

### 4.2 排版
- 段落间空一行（公众号阅读习惯）
- 关键句可加粗，但一屏不超过 3 处
- 列表和引用块适当使用，增加视觉节奏
- 第一段不缩进

### 4.3 结尾
- 不要用"你怎么看？欢迎留言"这种套路结尾
- 用一句话洞察或开放问题收尾，留余味

### 4.4 字数
- 深度科技文章：2500-4000 字
- 快评/资讯：1000-1500 字
- 教程/指南：2000-3500 字

---

## 五、写作后：素材回收

每次文章完成后，执行素材回收：

1. 这篇文章中提出了什么新观点？→ 补充到 `个人素材库/核心观点.md`
2. 这篇文章中用到了什么个人经历？→ 补充到 `个人素材库/个人经历.md`（如果是新的）
3. 这篇文章中测试/使用了什么工具？→ 补充到 `个人素材库/使用体验.md`
4. 有没有写出好的句子？→ 补充到 `个人素材库/金句碎片.md`

**素材回收和写作同样重要。这是素材库从零到一的过程。**
